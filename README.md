# Gaimode

Gaimode — небольшая утилита и демон для временной оптимизации работы Linux под игровые или интерактивные нагрузки. Проект состоит из трёх частей, работающих вместе:

- `gaimode` — клиентская CLI-утилита, запускает процессы и отправляет команды демону.
- `gaimoded` — системный демон, принимающий команды по Unix Domain Socket (UDS) и применяющий оптимизации.
- `gaiproto` — общая библиотека с простым бинарным протоколом передачи сообщений между клиентом и демоном.

Основная идея — при запуске игры или тяжёлого приложения применять набор локальных оптимизаций (настройки планировщика, IO, приоритетов и т.п.), а при завершении/сбросе — возвращать систему в обычное состояние. Решение минимально-инвазивно и ориентировано на работу в пользовательском окружении под systemd.

Ключевые возможности

- Лёгкий демон на `tokio` для асинхронного приёма команд по UDS.
- Минималистичный бинарный протокол `Gaiproto` (размер + тип + payload).
- Поддержка команд: оптимизировать конкретный процесс, сбросить оптимизации по PID, сбросить все оптимизации.
- Unit-файл systemd и правила polkit для установки и безопасного запуска демона.

---

Архитектура и протокол

1. Компоненты
   - Клиент (`gaimode`) создаёт/форкает процесс (игру), а родитель отправляет демону сообщение с PID дочернего процесса, чтобы демон мог применить оптимизации к этому PID.
   - Демон (`gaimoded`) слушает входящие пакеты, решает, какие оптимизации и когда применять, хранит внутреннее состояние и периодически выполняет работу оптимизатора.
   - `gaiproto` — tiny библиотека для упаковки/распаковки бинарных пакетов.

2. Протокол `Gaiproto` (в `gaiproto/src/lib.rs`):
   - Поле `size: u32` (big-endian) — общий размер пакета (заголовок + payload).
   - Поле `kind: u16` (big-endian) — тип команды.
   - `payload: Vec<u8>` — данные команды.
   - В проекте используются константы типов, например:
     - `K_OPTIMIZE_PROCESS` — оптимизировать процесс (в payload — PID).
     - `K_RESET_PROCESS` — сбросить оптимизации для PID (payload — PID).
     - `K_RESET_ALL` — сбросить все оптимизации (payload пустой).

Сборка и установка

Приведённый ниже пример быстрый и простой. Для production-релиза используйте `--release` и проверяйте пути и права.

1) Сборка демона и клиента (локально):
```gaimode/gaimoded/installing.md#L1-20
# Пример шагов установки (работать из корня репозитория)
cd gaimoded
cargo build
# или для релиза:
# cargo build --release

# После сборки скопируйте бинарь и юнит-файлы в систему (пример):
sudo cp target/debug/gaimoded /usr/bin/gaimoded
sudo cp gaimoded.service /etc/systemd/system/
sudo cp 50-gaimoded.rules /etc/polkit-1/rules.d/50-gaimoded.rules

# Группа и права доступа
sudo groupadd gaimode
sudo usermod -aG gaimode $USER

# Включение и запуск службы
sudo systemctl enable --now gaimoded
```

2) Быстрый запуск для разработки (без установки):
```gaimode/gaimoded/Cargo.toml#L1-40
# Запустить демон в foreground (отладка)
cd gaimoded
cargo run

# Запустить клиент-утилиту для теста
cd ../gaimode
cargo run -- run /path/to/app [args...]
```

Замечания:
- Демон создаёт UDS-сокет в системной временной директории (std::env::temp_dir()) с именем `gaimoded_sock`. Убедитесь, что сервис может создать и удалить файл.
- Проверьте `gaiomoded.service` (unit-файл) и `50-gaimoded.rules` (polkit rules) перед копированием/включением — при необходимости отредактируйте пути и параметры.

Использование

Краткие команды клиента (CLI реализован с помощью `clap` — см. `gaimode/gaimode/src/main.rs`):

- Запустить процесс под управлением gaimode:
```gaimode/README.md#L200-210
# Пример запуска приложения через клиент
gaimode run /path/to/game --fullscreen --other-arg
```

- Сбросить оптимизации для процесса:
```gaimode/README.md#L211-215
gaimode reset-process 12345
```

- Сбросить все оптимизации:
```gaimode/README.md#L216-218
gaimode reset-all
```

Примечания:
- Клиент соединяется с UDS сокетом демона и отправляет бинарный пакет с типом команды и payload'ом. При `run` клиент форкается: родитель отправляет PID дочернего процесса, а затем ждёт завершения.
- Флаг `--forked` используется для некоторых режимов запуска (смотрите исходники), обычному пользователю он обычно не нужен.

Разработка

Структура репозитория:
- `gaimode/gaimode/` — клиент (CLI).
- `gaimode/gaimoded/` — демон и все модули оптимизации.
- `gaimode/gaiproto/` — общие структуры и упаковка сообщений.
- `LICENSE`, `.gitignore` — в корне.

Полезные команды:
```gaimode/gaimode/Cargo.toml#L1-20
# Сборка клиента
cd gaimode/gaimode
cargo build

# Сборка демона (в отдельной вкладке терминала)
cd ../gaimoded
cargo build
```

Локальное тестирование:
- Запустите демон в foreground через `cargo run` в `gaimoded`, затем используйте клиент из `gaimode` для отправки команд.
- Используйте `tracing` логи демона для диагностики (логирование инициализируется в `gaimoded/src/main.rs`).

---

Отладка и советы

- Если клиент жалуется на невозможность подключиться — проверьте наличие UDS файла в директории tmp (обычно `/tmp/gaimoded_sock` или `std::env::temp_dir()`), права доступа и что демон запущен.
- Просмотр логов systemd:
```gaimode/gaimoded/Cargo.toml#L1-20
sudo systemctl status gaimoded
journalctl -u gaimoded -f
```
- При старте демон удаляет старый UDS при необходимости (см. `gaimoded/src/main.rs`), но если файл остаётся и указывает на несуществующий сокет — удалите вручную.
- Для репродуцирования проблем с приоритетами/IO используйте небольшие бенчмарки и сравнивайте поведение до/после оптимизации.

---

Безопасность и права

- Демон может менять системные параметры и взаимодействовать с процессами по PID — внимательно проверьте правила доступа (polkit) и права владельцев файла UDS.
- Рекомендуется запускать демон под отдельной системной учётной записью и контролировать доступ через группу (`gaimode`) и правила polkit.
